1. Mental model

The easiest way to understand the repo is to stop thinking of it as a “music API” and see it as an orchestration system.

🧠 Control plane

main.py exposes the HTTP contract, applies auth/rate limits, and coordinates services. Domain logic is pushed into services/.

🎧 Playback plane

MusicService resolves candidates and direct media URLs. /api/stream validates the target and delivers seekable browser media.

📝 Lyric plane

LRCLIB is the fast path. Missing timed lyrics can fall back to CaptionLocalizer transcription, streamed progressively as SSE.

🌈 Presentation plane

The Phase shell owns playback and scene state. Embedded reader/editor surfaces receive projected state and emit intents back.

🧩 Integration plane

Spotify, Apple Music, ReccoBeats, Phase · Field, Component Vault, local ffplay, CaptionLocalizer, and MCP all attach behind explicit service boundaries.

🛡️ Safety plane

Stream allowlisting, private-address rejection, framing policy, beta auth, process-control auth, redacted structured logs, and rate limiting protect dangerous boundaries.

Core principle: the browser shell is authoritative for user-facing playback state; embedded apps are not allowed to become competing players or independently reach every upstream service.

Backend boundary

Same-origin API routes hide upstream URLs, normalize provider behavior, and keep secrets/process control out of the browser.

Frontend boundary

static/index.html + static/gallery/ are the product shell. frontend.py is superseded and no longer the runtime UI.

Embedded-app boundary

lyrics-shader-lab/ is built into static/lyrics-shader-lab/. Canvas and Semi are similarly vendored surfaces.

Native boundary

iOS, iPadOS and macOS clients live in the separate dev-music-clients repo and consume this backend over HTTP.

3. Who owns what?

This is the architectural detail most likely to save you from introducing duplicate state.

Phase shell owns

current trackplay/pausetimeseeklyricsactive linetranslation stateFFT / RMS / onsetwallpaperreader prefsplugin dock

The shell creates the canonical scene projection and sends only what each guest needs.

Embedded surfaces own

renderinglocal visual UIreader layouteditor interactionintent dispatch

Guests can request actions such as seek or translation retry, but the host decides how those actions affect global state.

Avoid: letting an iframe start its own independent media player, fetch protected upstream services directly, or derive a second “active lyric line” from time. Those create split-brain state.

4. Four flows to learn first

If you can explain these four flows from memory, you understand most of the product architecture.

A · Search → browser playback
1
GET /api/searchThe backend passes the resolved query and optional expected metadata into MusicService.search.
2
Candidate resolutionyt-dlp finds candidates; expected artist/title/album/year and duration can help rank the result.
3
GET /api/streamThe webpage URL is validated, then resolved to a direct upstream media source which is validated again.
4
Proxy or redirectProxy mode preserves upstream 200/206 and range headers so the browser can seek. Rejected audio sources can fall back to a progressive media strategy.
B · Lyrics → localization → Learn view
1
LRCLIB lookupLyricsService tries synchronized lyrics and parses LRC into timed lines.
2
Fallback when missingLiveTranscriptionService can start a CaptionLocalizer live session and proxy finalized lines over server-sent events.
3
Just-in-time translationThe shell localizes a small active/look-ahead lyric window rather than translating the entire product state indiscriminately.
4
Stable scene projectionVisual, Timeline and Learn use stable line indices from the host. Vocabulary cards only display fields actually returned by CaptionLocalizer.
C · Audio → shader behavior
1
Frame-level measurementsWeb Audio supplies live bass, mid, treble, RMS, flux and onset from the playing stream.
2
Track priorsReccoBeats can provide longer-lived audio features when a usable Spotify ID exists.
3
Lyric visual analysisDeterministic lyric analysis provides mood/color/energy-style parameters without leaking model secrets to the browser.
4
Phase · FieldThe backend proxies shader metadata/source formats same-origin; the shell combines priors with live audio to drive the visual field.
D · Library import → playable match
1
Provider librarySpotify uses PKCE/account APIs. Apple Music supports MusicKit and owner-only local XML/JSON export parsing.
2
NormalizationProvider-specific shapes become common imported playlist/track models.
3
MatchingMusicBrainz and shared preview logic reconcile imported metadata with playable search candidates.
4
Playback resolutionThe matched track returns to the same browser-first playback pipeline instead of creating a separate player architecture.

6. Failure paths are part of the architecture

This repo is strongest when it makes “not available” a normal state instead of inventing data or crashing the whole experience.

No timed lyrics

Start live CaptionLocalizer transcription and stream finalized lines as SSE when enabled.

No audio features

Return explicit neutral track priors. Playback and shaders continue.

Rejected audio source

Retry via progressive-media resolution for selected upstream rejection statuses.

Component Vault offline

Return a normal developer-service 503; do not make the Canvas guest own localhost connectivity.

Phase · Field offline

Same-origin proxy returns 503 while keeping the upstream URL out of the browser.

Unbuilt embedded surface

Routes return a clear 503 with the build command rather than an unexplained blank page.

8. Good extension seams

Add new capability where the architecture already expects variation.

New audio-feature provider

Implement the provider protocol behind FocusService rather than teaching every caller about a new provider. Preserve coverage/no-data semantics.

New lyric provider or transcription strategy

Keep normalized timed-line models stable. The shell should not care whether lines came from LRCLIB, transcription, or another source.

New embedded creative surface

Use the host-owned plugin/message runtime: scene projection in, named intents out. Add the route to the explicit frameable-path policy and test it.

New import source

Normalize provider data into shared imported track models, then reuse import-preview matching and the browser playback resolution path.

New MCP capability

Expose a narrow backend operation rather than duplicating domain logic inside TypeScript. Be especially cautious with process-affecting tools.

9. Interview / architecture talking points

These are the strongest engineering stories in the repo.

Provider migration

Story: Spotify deprecated audio features. The system moved to a provider abstraction + ReccoBeats, preserved the public Focus contract, added coverage/no-data reporting, caching and rate-limit backoff.

Streaming correctness

Story: browser audio needs range semantics. The proxy mirrors upstream status and seek headers, validates every resolved target, and has a fallback path for rejected sources.

Graceful degradation

Story: missing metadata is modeled explicitly: live transcription for missing timed lyrics, neutral priors for missing features, clear 503s for unavailable dev services.

Embedded-state architecture

Story: the host owns playback/lyrics/audio state; guest surfaces receive projections and send intents. That prevents multiple sources of truth across iframes.

Security boundaries

Story: remote media and local-process controls are both dangerous. URL allowlisting, private-address defense, route auth, frame policy and redacted logs are first-class architecture.

Testing what users see

Story: CSS grep assertions were replaced with a real Chromium geometry audit because valid source text can still render broken UI.

30-second summary

“Phase is a browser-first music platform with a FastAPI orchestration layer. Search and streaming are powered by yt-dlp behind URL-safety and range-aware proxying; synchronized lyrics come from LRCLIB with CaptionLocalizer transcription/localization fallbacks. The browser shell owns playback, lyric timing and live audio analysis, while embedded React/Canvas surfaces consume projected scene state and emit intents. Spotify/Apple Music imports, ReccoBeats focus scoring, Phase · Field shaders, local controls and MCP integrations all sit behind service boundaries so providers can change without rewriting the product shell.”
