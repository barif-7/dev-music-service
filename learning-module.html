1. Mental model

The easiest way to understand the repo is to stop thinking of it as a “music API” and see it as an orchestration system.

🧠 Control plane

main.py exposes the HTTP contract, applies auth/rate limits, and coordinates services. Domain logic is pushed into services/.

🎧 Playback plane

MusicService resolves candidates and direct media URLs. /api/stream validates the target and delivers seekable browser media.

📝 Lyric plane

LRCLIB is the fast path. Missing timed lyrics can fall back to CaptionLocalizer transcription, streamed progressively as SSE.

🌈 Presentation plane

The Phase shell owns playback and scene state. Embedded reader/editor surfaces receive projected state and emit intents back.

🧩 Integration plane

Spotify, Apple Music, ReccoBeats, Phase · Field, Component Vault, local ffplay, CaptionLocalizer, and MCP all attach behind explicit service boundaries.

🛡️ Safety plane

Stream allowlisting, private-address rejection, framing policy, beta auth, process-control auth, redacted structured logs, and rate limiting protect dangerous boundaries.

Core principle: the browser shell is authoritative for user-facing playback state; embedded apps are not allowed to become competing players or independently reach every upstream service.

Backend boundary

Same-origin API routes hide upstream URLs, normalize provider behavior, and keep secrets/process control out of the browser.

Frontend boundary

static/index.html is the product shell, with styles in static/css/, state and startup in static/js/, and the gallery/plugin runtime in static/gallery/. frontend.py loads the shell HTML for the backend.

Embedded-app boundary

lyrics-shader-lab/ is built into static/lyrics-shader-lab/. Canvas, Semi, and the other catalogued plugins are similarly vendored surfaces declared in plugins.json.

Native boundary

iOS, iPadOS and macOS clients live in the separate dev-music-clients repo and consume this backend over HTTP.

3. Who owns what?

This is the architectural detail most likely to save you from introducing duplicate state.

Phase shell owns

current trackplay/pausetimeseeklyricsactive linetranslation stateFFT / RMS / onsetwallpaperreader prefsplugin dock

The shell creates the canonical scene projection and sends only what each guest needs.

Embedded surfaces own

renderinglocal visual UIreader layouteditor interactionintent dispatch

Guests can request actions such as seek or translation retry, but the host decides how those actions affect global state.

Avoid: letting an iframe start its own independent media player, fetch protected upstream services directly, or derive a second “active lyric line” from time. Those create split-brain state.

6. Failure paths are part of the architecture

This repo is strongest when it makes “not available” a normal state instead of inventing data or crashing the whole experience.

No timed lyrics

Start live CaptionLocalizer transcription and stream finalized lines as SSE when enabled.

No audio features

Return explicit neutral track priors. Playback and shaders continue.

Rejected audio source

Retry via progressive-media resolution for selected upstream rejection statuses.

Component Vault offline

Return a normal developer-service 503; do not make the Canvas guest own localhost connectivity.

Phase · Field offline

Same-origin proxy returns 503 while keeping the upstream URL out of the browser.

Unbuilt embedded surface

Routes return a clear 503 with the build command rather than an unexplained blank page.

8. Good extension seams

Add new capability where the architecture already expects variation.

New audio-feature provider

Implement the provider protocol behind FocusService rather than teaching every caller about a new provider. Preserve coverage/no-data semantics.

New lyric provider or transcription strategy

Keep normalized timed-line models stable. The shell should not care whether lines came from LRCLIB, transcription, or another source.

New embedded creative surface

Declare the surface in plugins.json so routing, framing, launchers, and builds share the same catalogue. Use the host-owned plugin/message runtime: scene projection in, named intents out, and test the integration.

New import source

Normalize provider data into shared imported track models, then reuse import-preview matching and the browser playback resolution path.

New MCP capability

Expose a narrow backend operation rather than duplicating domain logic inside TypeScript. Be especially cautious with process-affecting tools.

9. Interview / architecture talking points

These are the strongest engineering stories in the repo.

Provider migration

Story: Spotify deprecated audio features. The system moved to a provider abstraction + ReccoBeats, preserved the public Focus contract, added coverage/no-data reporting, caching and rate-limit backoff.

Streaming correctness

Story: browser audio needs range semantics. The proxy mirrors upstream status and seek headers, validates every resolved target, and has a fallback path for rejected sources.

Graceful degradation

Story: missing metadata is modeled explicitly: live transcription for missing timed lyrics, neutral priors for missing features, clear 503s for unavailable dev services.

Embedded-state architecture

Story: the host owns playback/lyrics/audio state; guest surfaces receive projections and send intents. That prevents multiple sources of truth across iframes.

Security boundaries

Story: remote media and local-process controls are both dangerous. URL allowlisting, private-address defense, route auth, frame policy and redacted logs are first-class architecture.

Testing what users see

Story: CSS grep assertions were replaced with a real Chromium geometry audit because valid source text can still render broken UI.

30-second summary

“Phase is a browser-first music platform with a FastAPI orchestration layer. Search and streaming are powered by yt-dlp behind URL-safety and range-aware proxying; synchronized lyrics come from LRCLIB with CaptionLocalizer transcription/localization fallbacks. The browser shell owns playback, lyric timing and live audio analysis, while embedded React/Canvas surfaces consume projected scene state and emit intents. Spotify/Apple Music imports, ReccoBeats focus scoring, Phase · Field shaders, local controls and MCP integrations all sit behind service boundaries so providers can change without rewriting the product shell.”

The one idea to hold onto.

Two signals feed the visuals and never get confused: live FFT (the current audio frame, audio.js) is the source of frame-by-frame truth and drives motion; the track-level profile (per-track audio features, reactivity.js) only biases/calibrates it. 01 Backend & services

The backend is a FastAPI surface (main.py, 1,927 lines) over 26 stateless service modules. Routes validate input with Pydantic models, rate-limit with slowapi, log structured events with structlog (auto-redacting secrets), enforce private-beta auth, and funnel every error through one translator.

The error-translation seam

Every route body ends with fail_with_http_error(exc) — one function maps domain exceptions to HTTP status codes, so service code raises plain exceptions and never imports FastAPI status logic.

def fail_with_http_error(exc: Exception) -> None:
    if isinstance(exc, HTTPException):       # already shaped — re-raise
        raise exc
    if isinstance(exc, LyricsRequestError):   # 400 bad input
        raise HTTPException(status_code=400, detail=str(exc)) from exc
    if isinstance(exc, LyricsNotFoundError):   # 404 not found
        raise HTTPException(status_code=404, detail=str(exc)) from exc
    if isinstance(exc, (ImportPreviewError, MusicServiceError, MetadataServiceError,
                        SpotifyImportError, VideoServiceError, httpx.HTTPError)):
        raise HTTPException(status_code=502, detail=str(exc)) from exc  # upstream failed
    raise HTTPException(status_code=500, detail=str(exc)) from exc
main.py — domain errors in, HTTP errors out. Services stay framework-agnostic.

Lifespan: warm the clients, close them cleanly

On startup the app pre-establishes TLS connections for persistent httpx clients (MusicBrainz, Spotify, ReccoBeats, Phase Field, StillShot, Sketchfab, Canvas, Component Vault) and fetches a Spotify client-credentials token. Shutdown closes every long-lived client.

02 Security & auth

The project has three security surfaces: SSRF defense for the stream proxy, a private-beta auth system with HMAC-signed sessions, and control-auth for machine-to-machine routes. All logging auto-redacts secrets.

SSRF defense in depth

Before the server will fetch a stream URL it must pass all of: an allowed scheme, a resolvable host, not a private/loopback/link-local/reserved address, and a host on the allowlist (googlevideo.com, youtube.com, …).

def validate_stream_url(url: str) -> str:
    parsed = urlparse(url)
    if parsed.scheme not in {"http", "https"}:  raise HTTPException(403, ...)
    if not parsed.hostname:                       raise HTTPException(403, ...)
    host = parsed.hostname.lower().rstrip(".")
    if _is_private_or_local_host(host):          raise HTTPException(403, ...)
    if not _host_allowed(host):                  raise HTTPException(403, ...)
    return url

Redirects are followed manually, re-validating each hop and capping the chain at 3:

async def open_validated_stream(client, url, headers, max_redirects=3):
    current_url = validate_stream_url(url)
    for _ in range(max_redirects + 1):
        response = await client.send(req, stream=True, follow_redirects=False)
        if response.is_redirect:
            current_url = validate_stream_url(urljoin(current_url, location))  # re-check!
            continue
        return response

Private beta auth

The beta_auth_gate middleware enforces session-based access when beta_auth_enabled is true:

  • Session tokens — HMAC-SHA256 signed (base64 payload + signature), stored in an httponly, secure, samesite=lax cookie. Sessions carry email and expiry (7-day TTL).
  • Invite flow — POST /api/auth/login validates email against an allowlist + invite code via constant-time comparison. Rate-limited 10/min.
  • Owner routes — Apple Music library export, persistent library access, and Spotify configuration are owner-only (beta_owner_email).
  • Per-user storage — Focus profiles stored in per-user subdirectories keyed by SHA-256 hash of email.
  • Public bypass — Health, login, auth endpoints, static files, and stream endpoints bypass the gate.
  • Open-redirect prevention — safe_next_path() validates redirect targets are same-origin.

Security headers

Every response gets: X-Content-Type-Options: nosniff, Referrer-Policy: same-origin, and X-Frame-Options — SAMEORIGIN for frameable plugin paths (checked via plugin_catalog.is_frameable()), DENY for everything else.

Why mirror 206.

If the server collapsed a partial response into a flat 200, the browser would never learn the track duration or be able to seek past the first buffered chunk. Faithfully passing through the range headers is what makes a dumb <audio> tag behave like a real player.

Control-route auth & log redaction

  • Control auth — local/MCP control routes (/play, focus profile writes, MCP start/stop) require a bearer or x-dev-music-token when DMS_CONTROL_AUTH_TOKEN is set; on Vercel they're refused outright if no token is configured.
  • Redaction — redact_sensitive_data is a structlog processor that recursively masks any key containing authorization / cookie / credential / secret / token / verifier before logs are rendered, so tokens never leak into JSON logs.

03 Music services

Five services handle the core music pipeline: search, metadata, lyrics, video, and local playback. Each is stateless and framework-agnostic — they raise plain exceptions and know nothing about FastAPI.

MusicService — YouTube search & streaming

The core engine. Uses yt-dlp with android_vr player client for reliable extraction. Audio format preference chain: m4a > webm > bestaudio > mp4 > best.

When the caller knows the duration/title/artist, MusicService.search() oversamples (fetches extra candidates) so it has room to rerank, then picks the best by a composite score:

def _entry_score(entry, query, target_duration, expected_artist, expected_title, ...):
    score = combined_score(...)               # normalized + fuzzy identity match
    if target_duration and duration:
        delta = abs(duration - target_duration)
        if delta > 5:                       # ±5s tolerance window
            score -= min(60.0, delta - 5)   # 1pt / extra second, capped
    score += _channel_quality_bonus(entry)  # "- Topic" +25, VEVO/official +15
    for bad in ("cover","karaoke","remix","sped up","8d audio", ...):
        if bad in lowered: score -= 12; break   # demote non-canonical variants
    return score

Candidates more than 10× the tolerance off in duration are hard-dropped (kills live versions/loops). The result is the canonical studio audio winning over covers and hour-long uploads.

The expensive part of playback is yt-dlp extraction. The search extraction already resolved each candidate's direct audio URL + request headers, so _search_entries writes them into the stream cache up front. The follow-up /stream call is then a cache hit instead of a second full extraction:

for entry in entries:                     # only freshly-extracted entries reach here
    wp, direct = entry.get("webpage_url"), entry.get("url")
    if wp and direct:
        MusicService._cache_set(                  # prime the stream cache
            MusicService._stream_cache, wp,
            (direct, dict(entry.get("http_headers") or {})),
            MusicService._STREAM_TTL_SECONDS,
        )
▲
Why it matters.

Both search and stream caches use 3-hour TTLs (under YouTube's 6-hour URL expiry). The cache is guarded by a single threading.Lock because yt-dlp runs in a threadpool via run_in_threadpool.

MetadataService — fused autocomplete

Searches MusicBrainz recordings with Lucene queries and fuses with Spotify search results. When both sources agree on a match, confidence is boosted. Results ranked by blended fuzzy + Lucene score. An author index (max 500 entries) enables fast prefix matching. Rate-limited to 1 request/second for MusicBrainz compliance. Cover art fetched from Cover Art Archive.

LyricsService — three-path localization

The lyrics pipeline has evolved from a simple LRCLIB fetch into a sophisticated three-path localization system:

Path 1

Inline first-window

The initial response includes translations for the first N lines (configurable window), computed synchronously before the response is sent.

Path 2

Background fill

A background thread translates remaining lines asynchronously, populating the cache for subsequent requests.

Path 3

Just-in-time window

As the playhead advances, POST /api/lyrics/localize-window translates the upcoming lyric window on demand.

All translations are cached per (track, locale) key. The LyricsLocalizationService is a thin bridge to CaptionLocalizer's HTTP endpoint, mapping timed LyricsLine objects to segments by stable line index. Failures are non-fatal — the original lines are returned.

VideoService — music videos, shorts, live

Uses flat extraction for fast search, then scoring with identity match (title/artist fuzzy), official channel bonus, and kind-specific logic: shorts must be ≤75s, live uses keyword matching. Format chain prefers combined audio+video mp4 at ≤480p. Stream URLs cached 4 minutes.

Translated vocals

TranslatedVocalsService creates timed translated-vocal segment plans with voice policy enforcement:

  • neutral mode — no voice profile, no consent required
  • user_consent / licensed — requires profile_id + consent_token
  • artist_clone — blocked outright

Tries Pika batch TTS backend first, then per-segment TTS, then local macOS say + ffmpeg fallback. Generated audio files stored in a content-addressed directory.

LyricVisualService — deterministic visual direction

Maps lyric text to visual parameters without external model calls. Keyword-based mood detection (calm, euphoric, sad, aggressive, dreamy, chaotic) weighted by section energy. Produces color pairs, brightness/chaos/pulse parameters, and visual prompts. Also shapes audio features for neutral and provider modes.

  • 7 palettes — matching the wallpaper color system
  • Configurable — bands, response speed, gain, height, axis, curve, flow, spacing, opacity, finish

Motion safety

motion-safety.js respects prefers-reduced-motion by slowing the shader clock per wallpaper's a11y risk rating. Each wallpaper declares its risk level; high-risk shaders (rapid strobing, chaotic motion) get stronger dampening.

A beat is declared when spectral flux exceeds an adaptive threshold (mean + 1.4·σ over a rolling window) and enough time has passed. The inter-onset interval feeds a median-based BPM estimate, smoothed exponentially:

if(flux > fAvg + 1.4*Math.sqrt(fVar) && flux>0.008 && t-this._lastBeat>0.16){
  const ibi = t - this._lastBeat;            // inter-onset interval
  if(ibi>0.25 && ibi<2.0){                   // plausible 30..240 bpm
    this._ivl.push(ibi); if(this._ivl.length>8) this._ivl.shift();
    const est = this._estBpm(this._ivl);
    if(est) this.bpm = this.bpm ? this.bpm + (est-this.bpm)*0.25 : est;
  }
  this._anchor = t; this._onset = 1; this._lastBeat = t;
}
this.pulse = Math.max(this._onset*this._onset, this.bass*0.55);

The per-band AGC (normalize against a slowly-decaying running max) is what lets a quiet mic and a loud track both drive the visuals with comparable range.

Focus mode (ADHD filtering)

FocusService scores tracks against a persisted focus profile (BPM range, instrumentalness floor, energy/valence bands). The score is a weighted blend:

focus_score = (
    bpm_proximity    × 0.40  # how close to target BPM range
  + instrumentalness × 0.35  # higher = more focus-friendly
  - speechiness      × 0.15  # penalty for spoken-word content
  - liveness         × 0.10  # penalty for live recordings
) × 100

Profile storage is pluggable: local JSON (per-user subdirectories keyed by email hash) or KV backend for hosted deployments.

ReccoBeats — replacing Spotify's deprecated endpoint

Spotify removed the /audio-features endpoint for new apps. 07 Patterns & takeaways

The same handful of ideas recur across the Python backend and the JS frontend. Recognizing them makes the whole codebase predictable.

Design patterns observed

Composition over inheritance

PlaybackRuleSet + rules instead of player subclasses; PlayerControls split from AudioPlayer. New behavior = new small object.

Strategy / plugin

Pluggable focus-profile storage (local-json | kv); reactivity profiles (rest/flow/spark/drive); two stream-delivery modes; injectable AudioFeatureProvider. All selected by config.

Proxy / adapter

The stream proxy, the same-origin shader proxy, the Canvas/Sketchfab/StillShot proxies, and the Component Vault MCP client all wrap a remote behind a clean local surface.

Layered signal (prior + live)

The mapper's "live FFT drives, track prior biases" is a disciplined fusion of a slow, reliable signal with a fast, noisy one.

Single owner / coalescing

The Wallpaper singleton serializes all state transitions and coalesces requests made mid-flight — no race between crossfade and the next switch.

Error translation seam

fail_with_http_error keeps services framework-free; the route layer is the only place that knows HTTP status codes.

Cache priming & intent-encoding TTLs

Search primes the stream cache; TTLs encode upstream expiry (3h for YouTube URLs, 24h for audio features, 900s for metadata, 4min for video).

Catalog-driven routing

Plugin surfaces are declared in plugins.json and everything — backend routes, frontend launcher, Vercel rewrites, build scripts — reads from that single source of truth.

postMessage protocol

The Base44 scene/frame/events/intents protocol is a clean iframe boundary: the host owns state, the plugin owns its view, communication is typed and directional.

Graceful degradation

Neutral visual profile, audio-features-unavailable payloads, tainted-canvas fallback, bundled shader fallback, negative caching — every optional layer fails soft.

Security patterns

  • SSRF defense in depth — scheme + host + private-IP + allowlist checks, applied to the first URL and every redirect hop.
  • Private beta auth — HMAC-signed sessions, invite-code validation with constant-time comparison, per-user storage, owner-only routes.
  • Least exposure on Vercel — local playback and unauthenticated control routes are refused in the serverless runtime.
  • PKCE, no secret in the browser path; tokens in httponly/secure/lax cookies.
  • Log redaction by construction — a structlog processor masks secret-shaped keys before any log is emitted.
  • Rate limiting per route with slowapi (e.g. stream 30/min, search 60/min, OAuth 10/min, Apple Music import 5/min).
  • Voice policy enforcement — artist cloning blocked, consent tokens required for user-specific voice modes.
  • Frame control — X-Frame-Options set to SAMEORIGIN only for declared plugin paths, DENY for everything else.

Takeaways for a developer joining this repo

  1. Start at main.py for the API surface and models.py for the contract; services are stateless classes you can read in isolation.
  2. To change how the music feels visually, edit the T block in mapper.js — not the shaders or the engine wiring.
  3. To change which audio wins a search, edit _entry_score in music_service.py.
  4. Anything that fetches a remote URL must go through validate_stream_url / open_validated_stream.
  5. The frontend shell has no build step — 28 scripts load in a fixed order in index.html; respect it (state → shaders → data → reactivity → mapper → engine → audio → player → service → app → features → plugins → init).
  6. To add a new plugin: add an entry to plugins.json, vendor the build into static/{id}/, and optionally write a bespoke *-plugin.js host. The build system, Vercel config, and route registration all read from the catalog.
  7. Optional layers must fail soft. Match the existing pattern: catch, log/ignore, fall back to neutral.
  8. For audio features: the AudioFeatureProvider protocol is the seam. Implement get_features() and get_features_bulk(), return None honestly when unavailable.
  9. For lyrics localization: the three-path system (inline, background, just-in-time) means the first response is fast, and subsequent reads hit cache.
  10. The beta auth middleware runs on every request. Public paths are exempted by pattern — add new public paths to the bypass list, don't skip the middleware.
